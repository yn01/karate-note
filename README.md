# 空手ノート（karate-note）

空手道場の紙の「空手ノート」を、道場生・保護者・先生（指導者）の3者をつなぐ仕組みにする Web アプリ。Built with Claude: Japan 2026 の提出作品。

> ⚠️ **このアプリのデータはすべて架空です。** 登場する道場生・保護者は実在の人物ではありません。

- **何を**：稽古のあとの紙のノートと、先生との1対1のことばを、次の稽古と家庭につなぐ。
- **だれに**：道場生（小学生）・保護者・先生。目標を持つのは道場生本人で、保護者は応援する側。
- **Claude の役割**：ノートを読み取り、答えを教えずに問いかける（道場生本人とのやりとりなので、その場で返す）。先生の育成計画と道場の知見から先生あての下書きを作り、別の Claude が点検する。保護者へのお便りと次のテーマの候補は、先生が直して承認したものだけが届く。

## 触ってみる（審査員の方へ）

**公開 URL：https://karate-note.vercel.app/** （ログイン不要のデモモード。スマホでの表示を想定しています）

1. 開くと、最初に「空手ノート」の画面（スプラッシュ）が出ます。「はじめる」で、道場生「たくやくん」（架空・小4・10級 水色帯）のホームへ。黒帯への道のりと現在地、今日のテーマ、本人の目標（本人が直せます）を見られます。
2. 画面上部の「道場生／保護者／先生」で、3つの立場を行き来できます（先生＝指導者の画面）。
3. 画面のいちばん上（切り替えバーの上）に「架空のデータです（デモ）」と出ています。
4. ホームの「ノートを取りこむ」→「見本のノートを使う」で、架空の手書きノート（11月1日）を Claude が読み取ります。結果を確かめて直し、保存できます。スマホなら「ノートを撮る」でカメラも使えます（写真はどこにも保存しません）。
5. ホームの「ふりかえりの質問」で、Claude の問いかけ（オープン質問 → 選択肢のある質問 → まとめ）を体験できます。道場生の画面は漢字にふりがな付きで、右上の「ふりがな」で切り替えられます。
6. 上の「先生」→「たくやくんのノートを確認する」で、1対1のことば（稽古のあとに先生が話したこと）を「話して入力」または「見本のことばを入れる」で入れ、Claude が要点に整理します。先生が直して確定します。
7. 同じ画面で、到達基準のチェック（先生が付けます）→ Claude の下書き → 別の Claude の点検 → 先生が直して承認、まで進められます。
8. 承認すると、保護者の「今週のお便り」と、道場生の「次のテーマを選ぶ」（候補から選ぶか、自分の言葉で書きかえる）に届きます。承認する前は、どちらにも出ません。

> **デモを戻す**
> ログインのないデモなので、だれでも承認や上書きができます。最初の画面（[トップ](https://karate-note.vercel.app/)）のいちばん下にある「デモを戻す」で、いつでも架空のデータを入れ直せます（続けて押せるのは30秒おき）。
> - **最初から**：11月1日のノートを取りこむ前。ノートの取り込みから承認まで、流れを一から試せます。
> - **一周したあと**：11月1日のノート・問いかけ・1対1・先生の承認まで済んだ状態。お便りや次のテーマがすぐ見られます。

> **デモモードについて**
> 審査のために、ログインなしで3つの立場の画面をすべて見られるようにしています。上の切り替えバーは、このデモのためのものです。
> 実際に使うときは、道場生・保護者・先生がそれぞれログインし、自分の画面だけを見ます。保護者には自分の子どものお便りだけ、道場生には自分のノートだけが表示されます。どの立場でも、Claude の下書きは先生が直して承認するまで、道場生と保護者には届きません。

| 立場 | URL | できること |
| --- | --- | --- |
| 道場生 | [/student](https://karate-note.vercel.app/student) | 黒帯への道のり・現在地・今日のテーマ・本人の目標、ノートの取り込み（[/student/note](https://karate-note.vercel.app/student/note)）、ふりかえりの質問（[/student/question](https://karate-note.vercel.app/student/question)）、次のテーマを選ぶ（[/student/theme](https://karate-note.vercel.app/student/theme)） |
| 保護者 | [/parent](https://karate-note.vercel.app/parent) | 今週のお便り（先生が承認したものだけ） |
| 先生（指導者） | [/coach](https://karate-note.vercel.app/coach) | 道場生一覧と審査予定の設定、ノートの確認（[/coach/review](https://karate-note.vercel.app/coach/review)）：1対1のことば・到達基準のチェック・下書き・点検・直して承認 |

## なぜ作ったか

稽古は週1回、日曜の2時間。残りの166時間にも、先生の育成計画を届けたい。

- 先生が一人ひとりと話せるのは、稽古の前後の1対1で1人1分ほど。良いところを褒め逃すこともある。
- 子どもの半分ほどが、ノートに同じ反省（「もっとがんばる」）を書き続けていて、次の稽古につながっていない。
- 保護者は稽古をほとんど見られない。家で良かれと思って「もっと力強く！」と声をかけ、先生が直したい癖（受けの前に腕を反対に振る）を強めてしまうことがある。

作者は空手道五段で、道場を開いて9年。小学生から大人まで、20人ほど（うち子どもが18人ほど）を指導している。空手ノートは、他のスポーツのノートを参考に、作者が自分で始めたもの。指導者講習で、ノートは一人ひとりを理解する要だと確信した。でも、一人では回しきれなかった。帯ごとの課題に頼りがちで、一人ひとりの育成計画は頭の中にあっても十分に届けられていない。

だから、先生の頭の中にある育成計画と道場の知見を、稽古の外（ノート・家庭・保護者）まで届ける仕組みにした。「黒帯への道のり」を、一人ひとりの地図にする。大事にしたのは、勝ち負けや出来の判定ではなく、本人が「次にどうするか」を自分で決めること。Claude はその道すじを用意する役で、主役は先生と道場生。保護者は、選手を支える人（アントラージュ）として応援する側に立つ。

## 黒帯への道のりと育成計画

- **黒帯への道のり**：白帯（無級）→ 10級（水色）〜 1級（茶色）→ 黒帯（初段）。級ごとに審査の形・組手・基本がある（[data/seed/belts.json](data/seed/belts.json)）。審査は年4回（5・8・11・2月）。道場生のホームでは、道のりの上の「いまここ」と「つぎの目標」を見せる。
- **育成計画は2層**：
  - **道場共通**：帯ごとの課題と、形ごとの到達基準（[skills/kata/](skills/kata/)。MVP は平安二段）。
  - **一人ひとり**：本人の目標、保護者の願い、マイルストーン（期日つき）、今期の重点、強み。審査予定は先生が選ぶ。
- **到達基準のチェックは先生が付ける**（まだ／ときどき／安定）。Claude は技の出来を判定しない。道場生と保護者には段階や点数を見せず、「次に目指すこと」だけを届ける。

## 指導の考え方と機能の対応

| 考え方 | 機能 |
| --- | --- |
| プレーヤーズセンタード（目標は本人のもの） | 問いかけは答えを教えず、オープン質問 → 言葉にしにくければ選択肢のある質問。次のテーマは本人が候補から選ぶか、自分の言葉で書きかえる。目標は本人がホームで直す |
| 先生が承認するまで届けない | 下書き → 別の Claude の点検 → 先生が直して承認。保護者・道場生に届く項目は1か所（[src/lib/review-fields.ts](src/lib/review-fields.ts)）で取り出し、テストで守る |
| 保護者は応援する側（アントラージュ） | お便りは「見てほしいところ1つ」と「声かけのヒント」。「力強く」のような別の動きにつながりやすい言葉より、先生の合言葉（「引き手」）を使う。保護者に採点や見張りの役をさせない |
| 安全 | 家でできる自主練は狙い付きで、安全の決まり（大人がいる・広さ・床・やらないこと）を必ず添える。点検役が安全も確かめる |
| 1対1のことばを残す | 稽古のあとに先生が話したことを、その場で音声入力で文字にし、Claude が要点に整理する。音声は保存しない |
| 同じ反省が続くとき | 過去のノートを踏まえて「先週も『もっとがんばる』と書いていたね」と事実だけ伝え、今週のことを聞く |

## 既存のアプリとの違い

- **紙のノートをそのまま使う**：子どもは今までどおり紙に書き、撮るだけ。書く習慣と手で書く良さを残す。
- **Claude は答えを教えない**：振り返りを代わりに書くのではなく、本人が次にためすことを自分で決めるための問いかけ。
- **先生の承認を挟む**：Claude の下書き（お便り・次のテーマの候補）は先生あて。先生が直して承認したものだけが保護者と道場生に届く。ノートの読み取りと問いかけは、道場生本人とのやりとりなので、その場で返す（答えは教えない）。
- **道場の知見を先生が育てる**：問いかけ方・安全な自主練・育成の考え方・形ごとの到達基準を、先生が Markdown（[skills/](skills/)）で書き、Claude はそれを読んで動く仕組み。

よくある仕組みと比べると、次のように位置づけている。

| よくある仕組み | 空手ノート |
| --- | --- |
| 練習記録・日誌のアプリ（記録を残す・振り返る） | 記録は紙のまま。振り返りは Claude の問いかけで「どこを・どうする」まで小さくし、次の稽古のテーマを本人が決める |
| AI がアドバイスや評価を返すアプリ | Claude は答えも評価も返さない。技の出来の判定や点数は出さず、先生が付けた到達基準のチェックだけを使う |
| 連絡帳・お知らせのアプリ（先生 → 保護者） | 先生の育成計画と1対1のことばから Claude が下書きし、点検を通して先生が承認したお便りだけが届く。保護者には「見てほしいところ1つ」と「声かけのヒント」を渡し、採点や見張りの役はさせない |

## Claude の使い分け（アプリの中）

Claude を呼ぶ場面は5つです。モデルと effort は [src/lib/claude/models.ts](src/lib/claude/models.ts) の1か所にまとめています。出力はすべて構造化出力（JSON、zod のスキーマは [src/lib/claude/schemas.ts](src/lib/claude/schemas.ts)）です。

| 場面 | モデル | effort | 選んだ理由 |
| --- | --- | --- | --- |
| 1 ノートの読み取り | Claude Opus 5.5（`claude-opus-5-5`） | low | 手書きの画像を読む力 |
| 2 1対1のことばの整理 | Claude Haiku 5.5（`claude-haiku-5-5`） | low | 短いテキストの整理。速さ優先 |
| 3 問いかけ | Claude Sonnet 5.5（`claude-sonnet-5-5`） | low | 子どもを待たせない速さと、答えを教えない指示を守る力 |
| 4 下書き | Claude Opus 5.5（`claude-opus-5-5`） | high | 育成計画と形の知見を踏まえて考える |
| 5 点検 | Claude Opus 5.5（`claude-opus-5-5`） | medium | 下書きとは別の呼び出しで、原則に反していないかを確かめる |

### 設計のポイント

- **点検役は別の呼び出し**：下書きを作った Claude とは別に、原則（答えを教えていないか・判定や点数・保護者を管理役にしていないか・作り話・安全・伝わる言葉・計画とのずれ）を確かめ、直し案を先生の画面に出す。
- **点検した内容と承認する内容を結ぶ**：点検した下書きのハッシュ（点検のプロンプトの版を含む）を残し、承認のときに内容が変わっていたり点検していなかったりすれば、先生に確かめる。
- **道場の知見を読み込む**：[skills/](skills/) の Markdown を場面ごとにプロンプトへ入れる。Claude が作った叩き台は、先頭に「下書き」の印がある間は読み込まない（先生が確かめる前に子どもへの問いかけに混ぜない）。問いかけ方・自主練・育成の考え方の3つは、先生（作者）が確かめて印を消し、読み込んでいる（11/5）。形の知見（平安二段）は、先生が中身を書いている途中（書き終わると自動で読み込まれる）。
- **到達基準の状態は先生が付けたものだけ**：下書きの「到達基準との照合」は、先生のチェックを結合し、Claude にはコメントだけを書かせる。
- **ふりがな**：道場生に届く文は `{漢字|よみ}` の形で読みを持たせ、画面でふりがなにする。読みはひらがなだけ受け付ける。

### 守り

- 5場面はすべて共通の入口 `callScene()`（[src/lib/claude/call.ts](src/lib/claude/call.ts)）を通ります。
- 次のときは Claude を呼ばず（または呼んだ結果を使わず）、**保存済みのデモ応答**（[data/seed/demo-responses.json](data/seed/demo-responses.json)）で画面を続けます。
  - 1日（日本時間）に API まで届いた呼び出しの回数が `CLAUDE_DAILY_LIMIT`（既定 200）または場面ごとの上限（読み取り60・整理60・問いかけ150・下書き40・点検40）に達したとき。回数は DB の `claude_calls` で数えます（プロンプトや出力の中身は残しません）
  - API の障害・時間切れ・混雑、出力が形に合わないとき、断られたとき（断られたときは、Opus・Sonnet はまずサーバー側の fallback で別のモデルが試します）
  - `ANTHROPIC_API_KEY` がないとき、`CLAUDE_MODE=demo` のとき
- API キーはサーバー側の環境変数だけで読み、ブラウザに渡るコードからは読み込めません（`server-only`）。
- デモ応答で続けたときは、先生の画面には「保存済みのデモ応答です」、道場生の画面には「見本を出しています」「いまは見本の質問です」と出します。点検（場面5）のデモ応答は「点検できなかった」として返すので、点検していない下書きが「問題なし」に見えることはありません。
- Claude の出力（下書き）は、指導者が直して承認するまで道場生と保護者には届きません。これは [src/principles.test.ts](src/principles.test.ts) のテストでも守っています（道場生・保護者の画面と問い合わせが、下書きや点検の結果を読まないこと）。

## 開発での Claude の活用

- **CLAUDE.md**：設計の原則（答えを教えない・承認まで届けない・プレーヤーズセンタード・架空のデータだけ・キーはサーバー側だけ・「形」と書く）と作業ルールを最初に書き、Claude Code はそれに沿って作業した（[CLAUDE.md](CLAUDE.md)）。
- **Plan モード**：機能ごとに、計画を書いて作者が承認してから実装した。決めきれないところ（ふりがなの付け方、デモの戻し方など）は、計画の中で作者に選んでもらった。
- **レビュー役のサブエージェント**：実装のたびに、別のサブエージェントが原則に反していないかを確かめ、指摘を直してからコミットした。指摘の件数はタスクごとに [docs/metrics.md](docs/metrics.md) に記録した。
- **テスト**：原則をソースで確かめるテスト（[src/principles.test.ts](src/principles.test.ts)）と、小さな関数のテスト（`npm test`）。わざと違反を入れて落ちることも確かめた。
- **MCP・ブラウザでの確認**：画面は Claude Code のブラウザのプレビュー（MCP のツール）で、実際に操作して確かめた（公開版も）。
- **フック**：jev-dispatch が Claude Code のフックとして動き、指示ごとに判断を記録した（下）。計測とスクショのリマインドもフックで出す計画だったが、リポジトリには入れず、同じルールを CLAUDE.md に書いて守った（タスクごとに見積もり → 記録、区切りごとに撮るものを伝える）。
- **Skills**：Claude API の呼び出しは claude-api のスキルを読んでから書いた（構造化出力・effort・fallback）。
- **自作ハーネス**（このリポジトリには入れていない）：
  - **jev-dispatch**（モデルの振り分け）：指示ごとに、作業の種類・難しさ・会話の流れへの依存を判断し、軽いサブエージェントに任せるか、強いモデルに相談するかを勧める。この開発では 11/2〜11/4 に116件の指示を判断し、「任せる」を勧めたのは2件。ほとんどは「前の会話に依存する」「質問」などで、メインのモデル（Opus 5.5）のまま進めた。
  - **dev-forge・dev-gate・forge-ledger・skill-distiller**：この開発では使っていない（dev-gate・forge-ledger・skill-distiller は、期間の初めにマーケットプレイスになかった）。計測は forge-ledger の代わりに、[docs/metrics.md](docs/metrics.md) に手で記録した。
- **記録**：決めたこと・詰まったこと・次にやることを [docs/devlog.md](docs/devlog.md) に、日程を [docs/schedule.md](docs/schedule.md) に残した。

タスクごとに、始める前に PERT 三点見積もり（楽観・最可能・悲観）を出し、終わったら実績を記録した（[docs/metrics.md](docs/metrics.md)）。見積もりの前提は「Next.js/TypeScript に慣れた中級エンジニアが、AI を使わずに手で実装する場合」。目安の表は開発のあいだ固定し、見積もりは後から変えていない。

**途中集計（11/5 時点。機能凍結の 11/6 に更新します）**：終わった12タスク。T05（問いかけ）はスキルの仕上げ待ちで中断中、T12（README）は作業中のため含めていない。

| 見積もり合計 | 実績合計 | 短縮率 | タスクごとの短縮率の中央値 | レビュー指摘 |
| --- | --- | --- | --- | --- |
| 166.99 時間 | 4.10 時間 | 97.5% | 98.4% | 139件（原則違反17件・安全16件） |

- 見積もりは前提と目安にもとづく推定で、実測との比較は参考値です。
- レビュー指摘は、すべてマージ前に直したか、見送る理由を devlog に書いた。

## 試行錯誤の前後

- **点検の結果に英語の項目名が出た** → 点検のプロンプトで、下書きの項目を日本語の名前で書くよう指示した。前の点検結果が使い回されていたので、点検のプロンプトの版をハッシュに入れ、プロンプトを直したら点検し直すようにした。
- **次のテーマの候補がひらがなだけで読みにくかった** → 漢字を使い、`{漢字|よみ}` で読みを付けて、道場生の画面でふりがなにした。読み付きの見本を先生の画面にも出す。
- **承認していない手本のイラストが、保護者の画面にいつも出ていた**（レビュー役の指摘）→ 先生が承認したお便りに手本の文があるときだけ添える形に。立ち方の描き方が平安二段とずれるおそれがあったので、立ち方は描かず腕の動きだけにした。イラストは作者のイメージに合わせて道着・黒帯の人物に描き直した。
- **iPhone でふりがなの付いた漢字の間が広がった** → 読みを漢字の中央にそろえる設定にした。
- **期間前に想定していた問いかけが、答えを教えていた** → 計画書（期間前）の想定では、2問目の選択肢が「まっすぐうけた／はんたいにふってからうけた」で正しい動きがわかり、3問目で「せんせいも『ちからづよさは、ひき手とこしから』と言っていたね」と先生の直し方をそのまま伝えていた。レビュー役の指摘を受けて、先生の判断で、選択肢は本人の感じ方（「すっと動けた／動きにくいところがあった／よく覚えていない」）に、先生のことばは質問の向きを決める材料にだけ使う形に直した。問いかけ方の知見の叩き台（[skills/questioning.md](skills/questioning.md)）にも「正しい答えが1つだけ混ざった当てっこにしない」「先生の直し方をそのまま伝えない」と書いた。
- **点検役が本当の問題を見つけた** → 本物の Claude で下書きと点検を動かしたとき、点検役は4件の問題（自主練の場所と窓ガラス、答えを渡してしまう次のテーマ、「もっとがんばる」の繰り返し、「引き手」が保護者に伝わりにくい）を見つけ、先生の画面に直し案を出した。

## プライバシーの方針（1対1のことば）

- 音声はこのアプリには送られず、保存もしません。文字にする処理はブラウザ・OS の音声認識が行い（Chrome は Google、Safari は Apple のサーバーを使うことがあります）、このアプリには文字だけが届きます。
- デモでは、先生の声だけを文字にしています（道場生の声は入れていません）。
- 実際に使うときは、本人と保護者の同意を得てから使います。子どもの発言は要点だけを残し、そのまま長く記録しません。いまのデモでは先生が話した文字起こしを全文保存しているので、実運用では文字起こしを整理のあとに消す・短く保つなどに見直します。
- 端末の中だけで文字にできる音声認識（オンデバイス）が使えるブラウザでは、それを使うことを検討します。
- Claude が整理した内容は先生の画面だけに表示され、先生が直して承認したお便りだけが保護者と道場生に届きます。先生が確かめた整理は問いかけにも渡しますが、質問の向きを決める材料にだけ使い、道場生には引用しません。

## ハッカソンのあと

- **立場ごとのログイン**：道場生・保護者・先生がそれぞれログインし、自分の画面だけを見る。保護者は自分の子どものお便りだけ、道場生は自分のノートだけ。審査予定などは先生だけが設定できるようにする。
- **同意とプライバシー**：本人と保護者の同意を取る画面。1対1の文字起こしを整理のあとに消す・短く保つ。
- **人ごと・端末ごとの回数制限**。
- **カレンダー**（過去のノート・問いかけのまとめ・お便りを日付で見返す）、保存したノートの編集、平安二段以外の形の知見、挙動ごとの手本。
- **横展開**：地域のスポーツクラブ、職場の新人育成。

詳しくは [docs/roadmap.md](docs/roadmap.md)。

## データの出どころ

- `data/seed/` の JSON は、**ハッカソン期間前に作った架空の合成データ**です（主役の「たくやくん」、お母さん、一覧用の5人など）。実在の道場生の情報は入れていません。
- `data/seed/belts.json`（黒帯への道のり）は、作者の道場の昇級審査科目表をもとに入力したものです。流派名は出していません。
- `public/samples/` のノート画像も、期間前に作った架空のサンプルです。

| ファイル | 中身 |
| --- | --- |
| `belts.json` | 白帯（無級）→ 10級（水色）〜 1級（茶色）→ 黒帯（初段）。級ごとの形・組手・基本・受審資格 |
| `students.json` | 道場生（たくやくん＋一覧用の5人） |
| `development-plan.json` | たくやくんの育成計画（本人の目標・保護者の願い・マイルストーン・今期の重点・強み） |
| `notes.json` | 過去3週分のノート（サンプル画像と同じ）と、一覧の「未確認」用の短いノート |
| `criteria-checks.json` | 平安二段の到達基準のチェック（指導者が付けたもの） |
| `theme-selections.json` | 11月1日の「今日のテーマ」 |
| `exam-plans.json` | 先生が決めた審査予定 |
| `demo-inputs.json` | デモで取り込む11月1日のノートと、1対1のことば（指導者の声のみ）。「デモを戻す」の「一周したあと」では DB に入れる |
| `demo-responses.json` | 読み取り・整理・問いかけ・下書き・点検の想定。保存済みのデモ応答のもと。「一周したあと」では、この下書きを先生が承認したものとして入れる |

## セットアップ

必要なもの：Node.js 20.12 以上（公開版の関数は Node 22 以上を想定）、Neon（Postgres）のデータベース。

```bash
npm install
cp .env.example .env.local   # DATABASE_URL（Neon）と ANTHROPIC_API_KEY を入れる
npm run db:migrate           # テーブルを作る
npm run db:seed              # 合成データを入れる（何度流しても同じ結果）
npm run dev                  # http://localhost:3000
```
