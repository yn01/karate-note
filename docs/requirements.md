# 要件（MVP）

期間前の計画書（plan.md、リポジトリの外）をもとに、ハッカソン期間中の要件を書き起こしたもの。設計の原則・作業ルールは [CLAUDE.md](../CLAUDE.md) を正とする。データはすべて架空（[README](../README.md#データの出どころ)）。

## 1. 目的

稽古は週に数時間だけ。残りの時間にも、指導者の育成計画を届ける。紙の「空手ノート」を、道場生・保護者・指導者の3者をつなぐ仕組みにし、「黒帯への道のり」を一人ひとりの地図にする。

- **道場生**：振り返りが毎回「もっと頑張る」で、次の稽古につながらない → 問いかけで、自分で気づき、次にどうするかを自分で決める
- **保護者**：先生が何を直してほしいか知らない。良かれと思った声かけで癖がつく → 承認済みのお便りで、見てほしいところと声かけのヒントを知る
- **指導者**：伝えられるのは稽古前後の1分ほど。良い点を褒め逃す → 1対1のことば・育成計画・形の知見をもとにした下書きを直して承認する

## 2. 設計の原則（要約）

1. Claude は答えを教えない。オープン質問 → 言葉にしにくければ選択肢のあるクローズド質問。
2. 指導者が承認するまで、Claude の出力は道場生と保護者に届けない。
3. プレーヤーズセンタード。目標は本人のもの、保護者は応援する側。Claude は管理・評価せず、技の出来を判定しない。到達基準のチェックは指導者が付け、道場生と保護者には点数を見せず「次に目指すこと」だけを届ける。
4. 実在の道場生の情報を入れない。
5. API キーはサーバー側だけ。
6. 「形」と書く（「型」は使わない）。

## 3. MVP の範囲

- 対象はたくやくん1人分を通しで（小4・10級・水色帯 → 2027年2月の審査で9級・黄色帯、平安二段を練習中）。
- 道場の知見の中身は平安二段だけ（skills/kata/heian-nidan.md）。
- 黒帯への道のり：白帯（無級）→ 10級（水色）〜 1級（茶色）→ 黒帯（初段）。data/seed/belts.json。審査は年4回（5・8・11・2月）。
- 保険として、テキスト入力だけでも同じ流れが一周できる。

**MVP に入れない**：大会ノート、動画の解析、複数の道場生の分析（一覧は表示のみ）、基本と組手の知見、平安二段以外の形の知見、ログイン、カレンダー、保存したノートの編集。詳しくは [roadmap.md](roadmap.md)。

**11/4 に足したもの（小さく）**：スプラッシュ画面、道場生の目標の入力と表示、お便りの手本のイラスト2枚、審査予定の設定（先生の画面からプルダウンで選ぶ。ログインなし）。

### デモの流れ（たくやくん）

## 5. Claude を呼ぶ5場面

使うモデル名は `src/lib/claude/models.ts` に1か所でまとめ、README に表で示す。出力はすべて構造化（JSON、`src/lib/claude/schemas.ts`）。5場面とも共通の入口 `callScene()` を通る。

割り当て（T03 で決定）：1 読み取り＝Opus 5.5（effort low）、2 整理＝Haiku 5.5（low）、3 問いかけ＝Sonnet 5.5（low）、4 下書き＝Opus 5.5（high）、5 点検＝Opus 5.5（medium）。

| # | 場面 | 入力 → 出力 | モデル・機能の選び方 |
| --- | --- | --- | --- |
| 1 | ノートの読み取り | ノートの写真 → 日付・今日のテーマ・よかったこと・直したいこと | 画像の読み取りに強いモデル。構造化出力 |
| 2 | 1対1のことばの整理 | 文字起こししたテキスト → 指摘・本人の気づき・来週の宿題・保護者に伝えたいこと | 速いモデル。構造化出力 |
| 3 | 問いかけ | ノート＋過去のノート＋育成計画＋形の知見＋先生のことば → 次の質問（open / closed、選択肢） | 子どもを待たせない速いモデル |
| 4 | 下書き | ノート＋問いかけの記録＋先生のことば＋育成計画＋形の知見＋到達基準のチェック → 要約・褒めポイント・到達基準との照合・次回テーマ候補・自主練（狙い付き）・安全・計画見直しの提案・保護者へのお便り | 計画を踏まえて考える強いモデル |
| 5 | 点検 | 下書き → 原則に反していないか（答えを教えていないか・安全か・子どもに伝わる言葉か・育成計画や形の知見とずれていないか）と直し案 | 下書きとは別の呼び出し。結果は指導者画面に表示 |

プロンプトには skills/ の指導者の知見を場面ごとに読み込む（questioning.md・home-practice.md・coaching.md・kata/heian-nidan.md）。

## 6. 1対1のことば

- 本来は稽古前後の1対1の会話をその場で文字にする想定。デモでは指導者の声だけを文字にする（動画に「※デモでは指導者の声のみ」）。
- 文字起こしはブラウザの音声入力（Web Speech API、ja-JP）。使えない環境ではキーボードの音声入力でテキスト欄に入れる。
- 音声は保存せず、文字だけ保存する。実運用では本人と保護者の同意、子どもの発言は要点だけ残す、などに調整する（README に書く）。

## 7. データ

| データ | 主な項目 | テーブル |
| --- | --- | --- |
| 帯の課題（道場共通） | 白帯・10級〜1級・黒帯。形・組手・基本・受審資格・形の知見ファイル | `belts` |
| 形の知見 | skills/kata/*.md（DB には入れない） | — |
| 道場生 | 名前（架空）、学年、帯、保護者 | `students` |
| 育成計画（一人ひとり） | 本人の目標、保護者の願い、マイルストーン（期日つき）、今期の重点、強み | `development_plans`・`milestones` |
| 到達基準のチェック | 道場生×形の要点ごとの状態（まだ／ときどきできる／安定してできる）。指導者が付ける | `criteria_checks` |
| 1対1のことば | 日付、文字起こし、Claude による整理 | `one_on_ones` |
| ノート | 日付、今日のテーマ、よかったこと、直したいこと、読み取ったテキスト | `notes` |
| 問いかけの記録 | やり取り、質問の種類（open / closed）、まとめ | `question_sessions` |
| 指導者の確認 | 下書き、点検結果、直した後の内容、状態（下書き／承認済み） | `coach_reviews` |
| テーマの選択 | 選んだ候補、または書き直したテーマ | `theme_selections` |

道場生・保護者の画面に出す問い合わせは、`coach_reviews.status = 'approved'` のものだけに絞る。

## 8. 守り

- 1日の Claude 呼び出し上限（`claude_calls` で数える。`CLAUDE_DAILY_LIMIT`、既定200）。数えるのは API まで届いた呼び出し。超えたら保存済みのデモ応答（data/seed/demo-responses.json）を返し、画面に「保存済みのデモ応答です」と出す。`CLAUDE_MODE=demo` で常にデモ応答。
- API 障害時も、保存済みのデモ応答で一周できる。
- 公開は Vercel。審査員がログインなしで触れるデモモード。
